Lesson · BT205 Unit 2 — Algorithms

Algorithms, Complexities & Flowcharts

Dec-2020 Q3a literal: "Define algorithm? Characteristics?" plus Q4a "different ways to write an algorithm, pros and cons". This file is those 7 marks — and the flowchart + dry run is a common midsem long question.

Algorithm — definition (verbatim)

An algorithm is a finite, step-by-step procedure that takes
input, performs definite operations, and produces output -
terminating after a finite number of steps.

Recipe analogy for the examiner: ingredients (input) → numbered steps (procedure) → dish (output), and the recipe must END (finiteness).

5 characteristics (write numbered, 1 line each)

#CharacteristicMeaning
1InputZero or more values given from outside
2OutputAt least one result produced
3DefinitenessEach step precise, no ambiguity
4FinitenessTerminates after finite steps — never infinite
5EffectivenessEach step doable in finite time with pen and paper

Complexity — Big-O intuition (midsem short favourite)

Time complexity = how steps grow as input n grows.
Space complexity = how extra memory grows with n.
Big-O = worst-case ceiling: O(1) < O(log n) < O(n) < O(n log n) < O(n^2)
Code shapeComplexityExample
Single statementO(1)c = a + b
One loop over nO(n)linear search, array sum
Loop inside loopO(n²)bubble sort, matrix add

Ways to write an algorithm + pros/cons (Dec-2020 Q4a)

WayProsCons
Natural language (steps in English)Easy to start, no symbols to learnAmbiguous, long, no standard
Pseudocode (half-English, half-code)Precise, maps straight to C++Needs convention discipline
Flowchart (diagram)Visual, logic visible at a glance, great for loops/branchesClumsy for big programs, redrawing cost

Solved examples in great depth (with dry runs)

Given:   task + sample input  Find: steps/chart + trace table
Rule:    symbol per line; decision always has 2 exits (yes/no)
Solve:   write -> dry-run on tiny input -> state output
Check:   hand-trace matches claimed answer

Solved A — algorithm + flowchart: sum of first n numbers (midsem long)

Step 1: START
Step 2: READ n
Step 3: SET sum = 0, i = 1
Step 4: REPEAT while i <= n:  sum = sum + i;  i = i + 1
Step 5: PRINT sum
Step 6: STOP
Dry run (n = 4)isum
start10
pass 1–41→2→3→4→50→1→3→6→10
i = 5 > 4, exit510 ✓ (= 4×5/2)

Solved B — greatest of three numbers (decision-chain classic)

START -> READ a, b, c
IF a >= b AND a >= c -> PRINT a
ELSE IF b >= c -> PRINT b
ELSE -> PRINT c -> STOP

Dry run (7, 3, 9): a≥b true, a≥c false → check b≥c? 3≥9 false → PRINT 9 ✓.

Solved C — factorial + complexity label

READ n -> fact = 1, i = 1
WHILE i <= n: fact = fact * i; i++
PRINT fact -> STOP   | single loop -> O(n) time, O(1) space

Dry run n = 5: 1→1→2→6→24→120 ✓. Always append the Big-O line — 1 free mark.

Dry-run check: factorial of 5 changes as 1 → 1 → 2 → 6 → 24 → 120. The final i = 6 fails the loop condition, so the program stops with output 120 and time complexity O(n).
Dry-run traps
  • Off-by-one: trace i <= n vs i < n on paper — #1 flowchart mark-killer.
  • Diamond exits: every decision MUST show yes + no arrows labelled, else diagram incomplete.
  • START/STOP ovals: missing terminators = −1 even if logic is perfect.
  • Complexity of nested loops: two nested n-loops = O(n²), not O(2n). Say "multiply, don't add".
Special lines for extra marks
  • "An algorithm must terminate: finiteness separates an algorithm from a mere procedure."
  • "Pseudocode is the bridge: precise enough to code from, free of any single language's syntax."
  • "The dry run is the proof: traced values 0→1→3→6→10 certify the logic before any compiler."
  • End flowchart answers with complexity line (O(n)) + verified output.
Exam tips
  • Q3a skeleton: definition (1) + 5 characteristics table (3) + recipe line (1).
  • Q4a skeleton: 4 ways table with pros+cons (4) + "flowchart best for logic, program best for proof" close (1).
  • Flowchart long: symbols → chart → dry-run table → Big-O; draw with ruler, label arrows.

Algorithms — Quick Reference

Definition

finite steps: input → definite ops → output → terminates.

5 traits

input / output / definiteness / finiteness / effectiveness

Complexity

O(1) < O(log n) < O(n) < O(n log n) < O(n^2)
1 loop=O(n) / nested=O(n^2) / time=steps / space=memory

Symbols

oval START/STOP / parallelogram I/O / rectangle process
diamond decision(yes/no) / circle connector / arrow flow

4 ways

  • English: easy, ambiguous
  • Pseudocode: precise, code-ready
  • Flowchart: visual logic
  • Program: runnable proof

Model answer · 7 marks

Define algorithm + characteristics

An algorithm is a finite, step-by-step procedure that takes input, performs definite operations, produces output, and terminates.

ALGORITHM PIPELINE
+--------+    +--------+    +--------+    +--------+    +--------+    +--------+
| INPUT  |--->| STEP 1 |--->| ...    |--->| STEP n |--->| OUTPUT |--->| STOP   |
+--------+    +--------+    +--------+    +--------+    +--------+    +--------+

INPUT zero+ | steps precise + effective | OUTPUT one+ | STOP finite
TRAITS: 1 INPUT  2 OUTPUT  3 DEFINITENESS  4 FINITENESS  5 EFFECTIVENESS
  1. Input: zero or more supplied values define the problem.
  2. Output: at least one useful result is produced.
  3. Definiteness: every step has one clear meaning and no ambiguity.
  4. Finiteness: the procedure stops after a finite number of steps.
  5. Effectiveness: each operation is simple enough to be carried out in finite time.

Exam close: “An infinite procedure is not an algorithm; finiteness separates an algorithm from a mere procedure.”

Model answer · 7 marks

Ways to write an algorithm + pros/cons

Use a comparison table, then choose the representation that matches the task.

REPRESENTATION CHOICES
                             +------+------+
                             | PROBLEM     |
                             +------+------+
                                    |
+-------+------------------+------------------+------------------+
        |                  |                  |                  |
        v                  v                  v                  v
+-------+-------+  +-------+-------+  +-------+-------+  +-------+-------+
| NATURAL       |  | PSEUDOCODE    |  | FLOWCHART     |  | PROGRAM       |
| LANGUAGE      |  | precise       |  | visual        |  | executable    |
| easy / ambig  |  | language-free |  | hard to scale |  | syntax-heavy  |
+---------------+  +---------------+  +---------------+  +---------------+
          BEST FLOW: PLAN -> VISUALIZE -> CODE -> TEST
  1. Natural language is easy to start but can be long and ambiguous.
  2. Pseudocode is precise, language-independent, and close enough to code for implementation.
  3. Flowcharts make branches and loops visible but become unwieldy for large programs.
  4. A real program is executable proof, but syntax can hide the underlying idea.

Exam close: “Pseudocode bridges explanation and implementation; a flowchart makes control flow visible.”

  2. Label the yes and no arrows; do not leave a decision with one exit.

  4. Write the verified output and the time complexity beside it.

Exam close: box the output, state O(n), and mention that the dry run checks off-by-one errors.
