Lesson · BT205 Unit 2 — Control Flow

Statements & Control Structures — if, switch, Loops

"Statements and control structures" is syllabus-verbatim. Branching picks paths; loops repeat work. Every program from here on is if + loop + array — learn the three loop shapes cold and pattern/number programs write themselves.

Statements (the sentence types of C++)

StatementExample
Declarationint n;
Assignment/expressionn = 5; sum += i;
Input/outputcin >> n; cout << n;
Branchingif / else / switch
Loopingfor / while / do-while
Jumpbreak / continue / return / goto (avoid)

Branching — if ladder vs switch (when to use which)

if (marks >= 90)        grade = 'A';      // single choice
else if (marks >= 75)   grade = 'B';      // ladder: first true wins
else                    grade = 'C';

switch (day) {                             // menu on ONE integer/char
  case 1: cout << "Mon"; break;            // break or it FALLS through!
  case 2: cout << "Tue"; break;
  default: cout << "??";                  // catches the rest
}

Rule: ranges/conditions → if-ladder; fixed menu values → switch. Switch tests only int/char (no float, no ranges) — common viva trap.

Diagram — branch vs loop (draw this) 
BRANCH: one test, one path
  +------------------+
  |    Condition?    |
  +-----+--------+---+
        | yes    | no
        v        v
     Action A   Action B

LOOP: test before each round
    +-----+-----------+------------+---------+
    |       Test condition                   |
    +-----+-----------+------------+---------+
          | no        |            | yes
          v           ^            v
   +------+-----+     |            +-------+--------+
   |   Exit     |     |            | Loop body        |
   +------------+     |            +-------+--------+
                      |                    |
                      |                    v
                      |            +-------+--------+
                      |            | Next item        |
                      |            +-------+--------+
                      |                    |
                      +--------------------+

3 loops — shapes + when (memorize as table)

LoopShapeRunsUse when

Verified programs (g++ checked — memorize 3, derive the rest)

// P1: factorial (for) — input 5 → 120
int n = 5, f = 1;
for (int i = 1; i <= n; i++) f *= i;   // 1·1·2·3·4·5

// P2: prime test (for + break) — input 17 → Prime
int p = 17, prime = 1;
for (int i = 2; i * i <= p; i++)
    if (p % i == 0) { prime = 0; break; }  // divisor found → stop early

// P3: fibonacci (while) — first 6 → 0 1 1 2 3 5
int a = 0, b = 1, c = 0;
while (c < 6) { cout << a << " "; int t = a + b; a = b; b = t; c++; }

// P4: star triangle (nested for) — rows 4:
// *  / **  / ***  / ****
for (int r = 1; r <= 4; r++) {
    for (int s = 1; s <= r; s++) cout << "*";
    cout << "\n";
}
// OUTPUTS: 120 · Prime · 0 1 1 2 3 5 · triangle above
Loop picker: use for when the count is known, while when it is unknown, and do-while when the body must run once. Use break to leave a loop early and continue to skip one iteration.
Pattern trace: for three rows, the outer loop selects row r; the inner loop prints s stars while s ≤ r. The result is one star, two stars, then three stars.

Solved examples in great depth

Solved A — trace P4 for rows = 3 (nested-loop tracing short)

rinner sprints
11*
21, 2**
31, 2, 3***

Rule: outer = rows, inner = columns; s <= r grows the triangle. Flip to s <= 4-r+1 for inverted.

Solved B — sum of digits (while classic): n = 472 → 13

sum = 0; while (n > 0) { sum += n % 10; n /= 10; }
// 472: 2+0→2, n=47 → 7+2=9, n=4 → 4+9=13, n=0 stop ✓

Solved C — do-while menu (runs-once proof)

int ch; do { cout << "1.Add 2.Exit: "; cin >> ch; /* act */ } while (ch != 2);
// menu prints even if user instantly picks 2 — while() alone couldn't promise that
Loop traps
  • Missing break in switch: execution falls into the next case — most-demonstrated bug in class.
  • ; after for/while: for(...); { } loops nothing, block runs once. Silent killer.
  • do-while ends with ;: } while (x); — the one place a trailing semicolon is REQUIRED.
  • Prime loop bound: test divisors only while i*i <= p — full 2..p−1 works but wastes; write the smart bound.
Special lines for extra marks
  • "for counts what is known, while guards what is unknown, do-while guarantees the first run."
  • "break abandons the search; continue forgives one round — both keep loops honest."
  • "Nested loops multiply: r rows × s columns traces = rectangular thinking."
  • End program answers with sample input → traced values → boxed output.
Exam tips
  • Loop-difference 2-marker: table (shape/runs/use) + one example each.
  • Program 5-marker skeleton: logic line (1) + code (2) + trace table (1) + output (1).
  • Pattern program: always state outer=rows, inner=columns before code.

Cheat-Sheet · BT205 Unit 2

Control Flow — Quick Reference

Branches

ranges → if-ladder · menu(int/char) → switch (+break! +default)

Loops

for(counted, 0+) · while(tested, 0+) · do(menu, 1+)
break=exit · continue=skip-round · do ends with ;

4 programs

fact: f*=i · prime: % + break (i*i<=p) · fibo: a,b shift
triangle: outer rows, inner s<=r · digits: %10 + /10

Key definitions

  • Fall-through: missing break runs next case
  • Nested: loops multiply (rows×cols)
  • do-while: tests last, runs once

Exam checklist

  • ☐ Loop table (shape/runs/use)?
  • ☐ break in every case?
  • ☐ No stray ; after for?
  • ☐ Trace + boxed output?

Picker

known→for · unknown→while · once→do · found→break · bad→continue

Model answer · 3–5 marks

for vs while vs do-while

Choose the loop from the control condition, not from habit.

FOR: pre-test, runs 0+ times
                        +-------+--------+
                        |  Init: i = 1   |
                        +------+---------+
                               |
                                v
     +--------------------------+-----------------+
     |             Test: i at most n              |
     +---+---------+------------+-----------------+
         | no      |            | yes
         v         ^            v
   +-----+------+  |            +------+---------+
   |    Exit    |  |            |  Body: f *= i  |
   +------------+  |            +------+---------+
                   |                   |
                   |                   v
                   |            +------+---------+
                   |            |  Update: i++   |
                   |            +------+---------+
                   |                   |
                   +-------------------+

WHILE: pre-test, runs 0+ times
     +--------------------------------------------+
     |                Test: n > 0                 |
     +---+---------+------------+-----------------+
         | no      |            | yes
         v         ^            v
   +-----+------+  |            +------+---------+
   |    Exit    |  |            |   Loop body    |
   +------------+  |            +------+---------+
                   |                   |
                   |                   v
                   |            +------+---------+
                   |            |   Next item    |
                   |            +------+---------+
                   |                   |
                   +-------------------+

DO-WHILE: post-test, runs at least once
+----------------+
|   Show menu    |
+------+---------+
       |         ^                               |
       v         +-------------------------------+
    +--+-----------------------------------+
    |          Test: ch is not 2           |
    +--------------------------------------+
       | no                                | yes |
       v                                   +-----+
+------+---------+                               |
|      Exit      |                               |
+----------------+                               |  next round
  1. for is used when the number of iterations is known, such as array traversal.
  2. while is used when the number of iterations is unknown, such as digit processing.
  3. do-while tests after the body, so it runs at least once and requires the final semicolon.
  4. break exits a loop; continue skips the remaining statements in the current round.

Exam close: state “tests last, runs once” for do-while and give one example for each loop.

  1. State the algorithm in one line before writing code.
  2. Use a bounded prime loop (i * i <= p) and break when a divisor is found.
  3. Trace a tiny input in a table, showing loop variables and the running result.
  4. Box the exact output and state complexity when relevant.

Exam close: code without a trace is incomplete; the trace is the proof that the logic works.

Model answer · 3 marks

if-ladder vs switch

Use if for ranges and conditions; use switch for fixed integer or character menu values.

IF-LADDER: first true test wins
+--------------------------------------+
|       Test: marks 90 or more?        |
+-----+--------------------------------+
      | no                             | yes -> Grade A
      v
+-----+--------------------------------+
|       Test: marks 75 or more?        |
+-----+--------------------------------+
      | no -> Grade C                  | yes -> Grade B

SWITCH: one case is selected; break controls fall-through
+--------------------------------------+
|   switch(day): match case 1 or 2?    |
+-----+------------------+-------------+
      | no               | yes
      v                  v
default: Unknown -> End  v
    +--------------------+-----+
    |     First case body      |
    +--------------------+-----+
                         v
+------------------------+-------------+
|            break present?            |
+-----+------------------+-------------+
      | no               | yes -> End  ^
      v                                |
    +-+------------------------+       |
    |      Next case body      |       |
    +--------------------------+       |
                               |       | next round
                               +-------+
No break falls into the next case body; a last case with no break exits.
  1. An if-ladder checks conditions in order and the first true branch wins.
  2. A switch selects one fixed int or char value and uses break to prevent fall-through.
  3. switch does not directly test floating-point ranges; default handles unmatched values.

Exam close: state the use case, draw both exits, and mention the missing-break trap.
