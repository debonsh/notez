Lesson · BT205 Unit 1 — OS (highest weightage)

Operating System: Definition, Functions, Types & Management

Asked almost recurring (Dec-2020 Q2a pattern: "various functions of OS"). Master definition + 6 functions + 5 types + file/process/memory — that alone is 7 marks.

Definition (write verbatim — 2 versions, pick one)

An Operating System is system software that acts as an interface
between user/applications and hardware, and manages hardware +
software resources for efficient, convenient use.

Short form: OS = interface + resource manager + extended machine. Kernel = core part resident in memory; shell = outer command layer. First software at boot, last at shutdown.

Functions — 6, each with one mechanism (the 7-marker body)

#FunctionWhat OS actually does
1Process managementCreate/schedule/terminate; sync + communicate; PCB per process
2Memory managementAllocate/deallocate, track used/free, reduce fragmentation, protect processes
3File managementCreate/delete/copy, directories, permissions, backup, FAT/NTFS
4Device / I/O managementDrivers, spooling, buffering — CPU need not wait for slow printer. E.g. 3 users hit Print: jobs queue in the spool folder, printer eats them one by one, nobody's CPU waits
5Security + protectionUser accounts, passwords, access rights, antivirus hooks
6User interface + job controlCLI/GUI, program execution, error handling, accounting

Types — 5, evolution order (write as timeline)

TypeIdeaLimitation it fixes / example
1. Serial / sequentialOne job at a time, FIFO via program counterSimplest; CPU idle during I/O — e.g. early systems
2. BatchSimilar jobs batched on cards, run one by oneNo per-job input mid-run; prep waste — payroll batches
3. MultiprogrammingMany jobs in memory; CPU switches when one waits for I/OKills idle time — the big leap; needs memory protection
4. Time-sharing / multitaskingCPU slices shared among users (ms quanta)Interactive; each feels sole user — Unix, Windows
5. Real-time (hard/soft)Response within fixed deadlineReservation, ICU, missiles, robots; hard = must meet, soft = best effort

Also name with one example each if space remains: distributed (Google search across servers), network (office login server), mobile (Android), embedded (washing-machine controller).

File management in depth

File system = how OS stores, organizes, protects files on disk.
File = named bytes; Directory/folder = container; Path = route to file.
FAT / NTFS / ext4 = competing filing schemes (NTFS modern Windows).
OS doesExample
Create/delete/copy/move, open/read/writemkdir, cp, rm (Linux) / Explorer (Windows)
Directories + hierarchy/home/zevu/notes/ tree
Permissions + protectionchmod 755 notes.txt = rwxr-xr-x: you read/write/run, others only read — classmates can't delete your file
Backup, error detectionRestore points, journaling file systems

Process management in depth

Program = passive file on disk. Process = program in execution.
PCB (Process Control Block) = process's brain: PID, state,
priority, registers, memory limits, open files.

OS jobs: schedule on CPUs, create/delete/suspend/resume, sync (locks/semaphores), communicate (pipes/messages). States: new → ready → running → waiting → terminated.

Worked example — two processes, one CPU: you type in Word (process P1, PID 101) while a print job runs (P2, PID 102). CPU runs P1; P2 needs the slow printer, so OS marks it WAITING, saves its registers into its PCB, and gives CPU to P1. Printer finishes → interrupt → P2 back to READY. Without the PCB's saved registers, P2 could never resume mid-page. Same program twice (two Word windows) = two processes, two PIDs, two PCBs.

Memory management in depth

OS part-resides in RAM; rest split among processes.
Goals: use every byte, no process reads another's, no permanent holes.
JobMeaning
Allocate / deallocateGive on start, take back on end
Track + protectTable of free/used; fence processes apart
Fight fragmentationCompact/swap/page so holes don't waste RAM
Virtual memoryDisk pretends to be RAM (swap) — "logical > physical". E.g. 8 GB RAM + Photoshop needing 12 GB: idle Chrome tabs move to disk-swap, Photoshop runs; slower, but it runs instead of crashing
Fast distinctions: program = passive file on disk; process = active execution with a PCB. FAT is an older file system, while NTFS adds journaling and permissions. Hard real-time must meet a deadline; soft real-time prefers to meet it.
Process state check: READY means eligible for the CPU, RUNNING means currently executing, WAITING means blocked on I/O or another event, and TERMINATED means the PCB and memory are released. The scheduler moves a process among these states.

Numeral traps (concept traps)
  • Program ≠ process: file on disk vs execution + PCB in RAM. Swapping = zero.
  • Batch ≠ multiprogramming: batch = similar jobs piled, still idle; multiprog = overlap CPU with I/O wait.
  • Hard vs soft real-time: missile/ICU = hard (miss = disaster); video stream = soft (miss = glitch).
  • FAT vs NTFS: permissions + journaling = NTFS. Writing "FAT has permissions" is wrong.
Special lines for extra marks
  • "The OS is an extended machine: it hides hardware ugliness behind system calls like open, read and write."
  • "A process is a program in execution; its PCB is its brain — PID, state, priority, registers and limits."
  • "Memory management pursues efficient utilization with integrity: allocate, track, protect, defragment."
  • Close with: "Hence the OS is the mastermind — first at boot, last at shutdown."

OS — Quick Reference

The statement

OS = interface + resource manager + extended machine (kernel inside).

6 functions

process (PCB) · memory (alloc/track) · files (FAT/NTFS)
devices (spool) · security (accounts) · UI (CLI/GUI)

5 types (evolution)

serial → batch → multiprog (kill idle) → time-share (slices) → real-time (deadline)

processPCB, schedule, states
memoryalloc, protect, de-fragment

Key definitions

  • Kernel vs shell: resident core vs command outer layer
  • Program vs process: passive file vs execution+PCB
  • Spooling: queue slow I/O so CPU never waits

one job FIFO → serial · pile of similar → batch
idle-CPU fix → multiprog · interactive slices → time-share
fixed deadline → real-time (hard=missile, soft=video)

Model answer · 7 marks

Define OS + explain its functions

An operating system is system software that interfaces users and applications with hardware while managing resources efficiently.

+------------------+                    +------------------+                  +------------------+
| USERS / APPS     |-- system calls --->| OPERATING SYSTEM |-- drivers: OS->HW| HARDWARE: CPU/RAM|
|                  |                    | interface +      |                  | / DISK / DEVICES |
|                  |<--- returns to app | resource manager  |<-- HW interrupts |                  |
|                  |                    | + virtual machine|                  |                  |
|                  |                    | kernel: process, |                  |                  |
|                  |                    | memory, file,    |                  |                  |
|                  |                    | device; security |                  |                  |
|                  |                    | protect/CLI/GUI  |                  |                  |
+------------------+                    +------------------+                  +------------------+
  1. Process management: create, schedule, synchronise, communicate, and terminate processes using a PCB.
  2. Memory management: allocate, track, protect, deallocate, and reduce fragmentation.
  3. File management: organise directories, permissions, backup, and filesystems such as NTFS/ext4.
  4. Device management: use drivers, buffering, and spooling so the CPU need not wait for slow I/O.
  5. Security and interface: accounts, passwords, access rights, CLI/GUI, and job control.

Exam close: “The OS is the mastermind of the machine—first at boot, last at shutdown.”

Model answer · 7 marks

Types of operating systems

Tell the evolution as a story: each type removes a limitation of the previous one.

+-------------+ +-------------+ +-------------+ +-------------+ +-------------+
|  SERIAL     |>|  BATCH      |>| MULTIPROG   |>| TIME-SHARE  |>| REAL-TIME   |
|  one job    | |  job pile   | | many in RAM | | ms quanta   | |  deadline   |
|  CPU idles  | |  prep waste | |  CPU + I/O  | | interactive | | hard / soft |
+-------------+ +-------------+ +-------------+ +-------------+ +-------------+
TIME-SHARE = time-sharing
  1. Serial processes one job at a time; the CPU can remain idle during slow I/O.
  2. Batch groups similar jobs, reducing manual setup but still not solving CPU idle time.
  3. Multiprogramming keeps several jobs in memory and switches when one waits for I/O.
  4. Time-sharing gives each user short CPU quanta; real-time guarantees response by a deadline.

Exam close: hard real-time must meet the deadline; soft real-time makes the best effort. Use one current example for each.

Model answer · 5 marks

File / process / memory management

Use three short tables, each with the object, job, and one mechanism.

FILE FUNCTION
file request -> path/directory lookup -> permission check
                                          | \
                                          |  +-- allowed -> disk read/write + FS metadata
                                          v
                                          access error (denied)

PROCESS FUNCTION
NEW ---> READY ---> RUNNING ---> TERMINATED
           ^           |
           |           |
           +<----------+
           | time-slice preemption
           |           |
           |           +---> WAITING (I/O event)
           |                       |
           +<---- event/completion +

MEMORY FUNCTION
request -> allocate/track used/free -> relocate -> protect -> run -> deallocate

optional if fragmented -> compact, then relocate updated addresses
optional if paging enabled -> page in/out <-> disk-backed swap
  1. File management names, stores, protects, and retrieves files; directories and permissions organise access.
  2. Process management treats a program in execution as a process; the PCB stores PID, state, priority, registers, and limits.
  3. Memory management allocates RAM, protects processes, reduces fragmentation, and provides virtual memory when needed.

Exam close: explicitly write “program = passive file, process = active execution + PCB.”
