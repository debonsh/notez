Lesson · BT205 Unit 1 — Organization

CPU Organization, Registers, Bus Architecture & Instruction Set

The CPU is the brain; buses are the nerves; registers are its scratch-pad. RGPV asks: draw CPU block, list registers, explain 3 buses, define instruction set. All four live here.

CPU = ALU + CU (+ registers)

CPU (Central Processing Unit) = brain of computer.
ALU (Arithmetic Logic Unit):  + - * / and AND OR NOT comparisons.
CU (Control Unit):            directs everything, executes no data itself.
Registers:                    tiny, fastest storage inside CPU.
UnitDoesDoes NOT do
ALUAll arithmetic + logic; result to accumulatorNever controls I/O timing
CUFetches, decodes, issues control signals, moves dataNever computes on data itself
RegistersHold instruction, addresses, data being processedNever store programs permanently

Worked example — ADD inside the CPU: R1 = 12, R2 = 7. CU fetches ADD R1, R2, places operands on the ALU, ALU computes 19, result lands in ACC, then moves to R1. CU never touches the numbers — it only sends the "add now" signal. Flags set: zero = 0 (result ≠ 0), carry = 0, sign = 0 (positive).

FlagSet (=1) when…Example
ZeroResult is 05 − 5 = 0 → zero = 1 (used by ==)
CarryAddition overflows the word255 + 1 in 8-bit → carry = 1
SignResult negative3 − 9 = −6 → sign = 1

Registers — 8 to memorize (name + 1 line)

RegisterHoldsMemory trick
PC (Program Counter)Address of NEXT instruction"points ahead"
IR (Instruction Register)Current instruction being decoded"now serving"
MAR (Memory Address Reg.)Address sent TO memory"address out"
MDR (Memory Data/Buffer)Data coming FROM / going TO memory"data in transit"
Accumulator (ACC)ALU results + operands"ALU's desk"
Stack Pointer (SP)Top of stack (calls, returns)"pile pointer"
Status/FlagZero, carry, sign, overflow bits"result report card"
General purpose (R0–Rn)Temp data for programs"scratch pads"

Bus architecture — 3 buses, one table (high-frequency 7-marker)

A bus = set of parallel wires carrying signals between CPU, memory, I/O.
System bus = data bus + address bus + control bus together.
BusCarriesDirectionWidth decides
Data busActual data / instructionsBidirectional (CPU ↔ memory/IO)Word size (8/16/32/64-bit)
Address busAddress of location to read/writeUnidirectional (CPU → memory/IO)Max memory = 2^n (n lines)
Control busCPU commands; device IRQ/attention; clock/reset inputsMixed by signalTiming + coordination
Address-line rule: n address lines select 2n locations. Sixteen lines give 65,536 locations, or 64 KB when each location holds one byte.
Memory read, in order: the PC places the address in MAR → memory returns the instruction through MDR → the IR holds it for decoding → the CU issues control signals and the ALU executes. One read uses the address, control, and data buses together.

Instruction set + format

Instruction = order telling CPU what to do.
Instruction set = full vocabulary CPU understands (ADD, SUB, LOAD, STORE, JMP...).
Format:  [ OPCODE | OPERAND(s) ]
  opcode  = WHAT to do (ADD)      operand = WHERE / WHAT ON (R1, memory addr)

Example: ADD R1, R2 — opcode ADD, operands R1 R2. Decode two more: LOAD R1, [5000H] (opcode LOAD: copy memory cell 5000H into R1) and JMP 2000H (opcode JMP, one operand: set PC = 2000H, jump there). CISC = many complex instructions, e.g. Intel/AMD x86 in laptops; RISC = few simple fast ones, e.g. ARM in phones. One line comparing them is enough for RGPV — with these two chip examples attached.

Fetch–Decode–Execute cycle (4 steps, write numbered)

1. FETCH:   PC → MAR; memory → MDR → IR; PC = PC + 1
2. DECODE:  CU interprets opcode in IR; identifies operands
3. EXECUTE: ALU acts / data moves; flags update
4. STORE:   result → register/memory; repeat on next PC

Numeral traps
  • 2^n vs 2n: 16 lines = 2^16 = 64K, NOT 32. Memorize 2^10=1K, 2^20=1M, 2^30=1G.
  • Address bus direction: one-way CPU→memory. Writing "bidirectional" loses the mark.
  • CU computes nothing: never write "CU performs addition" — that is ALU + accumulator.
  • MAR vs MDR: MAR = address, MDR = data. One-letter swap, full mark lost.
Special lines for extra marks
  • "The control unit fetches, decodes and coordinates, but all computation occurs in the ALU."
  • "A single memory read uses all three buses: address selects, control commands READ, data returns."
  • "With n address lines the CPU addresses 2^n locations; hence 16 lines address 64 KB byte-wise."
  • End with a boxed cycle: FETCH → DECODE → EXECUTE → STORE.
Exam tips
  • Draw the CPU box (ALU+CU+registers) + memory + I/O + 3 buses — diagram = 2 marks.
  • Register table: write all 8 with full forms; RGPV deducts for abbreviations alone.
  • For "organization" 7-marker: order = CPU → registers table → buses table → cycle steps.

Model answer · 7 marks

CPU block diagram: ALU, CU, registers

The CPU is the processing and control centre. The ALU computes; the CU fetches, decodes, and coordinates; registers hold values currently needed by the CPU.

CPU INTERNALS
+------------+---------------------------------------------------------+
| UNIT       | ROLE                                                    |
| Registers  | PC IR MAR MDR ACC SP FLAGS R0-Rn                        |
| ALU        | operands -> arithmetic/logic/compare -> result/flags    |
| CU         | fetch, decode, sequencing, and bus control              |
+------------+---------------------------------------------------------+

SYSTEM-BUS SIGNAL DIRECTIONS
ADDRESS     CPU/MAR -----------------------> memory / I/O
DATA write  CPU/MDR -----------------------> memory / I/O
DATA read   CPU/MDR <------------------------ memory / I/O
CONTROL     CPU/CU -------------------------> memory / I/O
ATTENTION   device --------------------------> CPU
ACK         CPU/CU -------------------------> device
CLOCK       clock source -------------------> CPU + bus devices
RESET       reset source/controller ------> CPU + bus devices
  1. Draw the CPU box, ALU, CU, and registers before writing prose.
  2. State ALU functions: addition, subtraction, multiplication, division, comparison, and Boolean logic.
  3. State CU functions: fetch, decode, issue control signals, coordinate movement, and update the program counter.
  4. Name the registers with full forms: PC, IR, MAR, MDR, ACC, SP, status/flags, and general-purpose registers.

Exam close: “The CU directs the work; the ALU performs the data operations; registers provide the CPU’s fastest working memory.”

Model answer · 5 marks

Bus architecture + address math

A bus is a group of parallel wires carrying signals between CPU, memory, and I/O. A system bus contains data, address, and control buses.

+----------------------+------------+--------------------+--------------------+
| SIGNAL               | SOURCE     | DIRECTION          | DESTINATION        |
+----------------------+------------+--------------------+--------------------+
| Address              | CPU/MAR    | --------------->   | memory / I/O       |
| Data write           | CPU/MDR    | --------------->   | memory / I/O       |
| Data read            | memory/I/O | --------------->   | CPU/MDR            |
| Control commands     | CPU/CU     | --------------->   | memory / I/O       |
| Attention / IRQ      | device     | --------------->   | CPU                |
| Interrupt ACK        | CPU/CU     | --------------->   | device             |
| Clock                | clock gen  | --------------->   | CPU + bus devices  |
| Reset                | reset ctrl | --------------->   | CPU + bus devices  |
+----------------------+------------+--------------------+--------------------+

READ 5000H
  CPU/MAR ---- address 5000H ----> MEMORY
  CPU/CU  ---- READ ------------> MEMORY
  MEMORY  ---- instruction/data -> CPU/MDR

ADDRESS CAPACITY (byte-addressable)
  n address lines -> 2 power n locations
  16 lines: 65,536 locations = 64 KiB
  20 lines: 1,048,576 locations = 1 MiB
  32 lines: 4,294,967,296 locations = 4 GiB
  1. Data bus is bidirectional and its width indicates the word size.
  2. Address bus is unidirectional from CPU to memory/I/O; n lines address 2^n locations.
  3. Classify control signals by source: the CPU issues read/write commands, a device raises IRQ/attention, the CPU returns interrupt ACK, and clock/reset sources feed CPU and bus devices.
  4. One memory read uses all three buses: address selects, control commands, data returns.

Exam close: box the address result and write the direction of every bus beside its name.

Model answer · 5 marks

Instruction format + fetch-decode-execute

An instruction tells the CPU what operation to perform and on which operands. The instruction set is the complete vocabulary understood by the CPU.

INSTRUCTION WORD: ADD R1, R2
+-----------------------------------+
| opcode: ADD; operands: R1, R2     |
| WHAT operation ON what            |
+-----------------+-----------------+

START
                  |
                  v
+-----------------+-----------------+
| 1 FETCH                           |
| PC -> MAR; memory -> MDR -> IR    |
+-----------------+-----------------+
                  |
                  v
+-----------------+-----------------+
| 2 DECODE                          |
| CU reads opcode and operands      |
+-----------------+-----------------+
                  |
                  v
+-----------------+-----------------+
| 3 EXECUTE                         |
| ALU performs the operation        |
+-----------------+-----------------+
                  |
                  v
+-----------------+-----------------+
| 4 STORE / WRITEBACK               |
| result -> register or memory      |
+-----------------+-----------------+
                  |
                  v
+-----------------------------------+
| 5 PC OUTCOME                      |
| ordinary: next PC to FETCH        |
| branch: target PC to FETCH        |
| HALT: CPU enters STOP             |
+-----------------+-----------------+
  1. Fetch: PC supplies the address; MAR holds it; memory returns the instruction through MDR into IR; PC advances.
  2. Decode: CU interprets the opcode and identifies operands.
  3. Execute: ALU performs the operation and flags record the result.
  4. Store: the result goes to a register or memory, then the next instruction is fetched.

Exam close: box FETCH -> DECODE -> EXECUTE -> STORE and identify opcode versus operand in the example.
