Lesson · BT205 Unit 1 — Memory & I/O

Memory, Storage Systems & I/O Devices

The only Unit-1 topic with real numerals: KB/MB/GB conversions and 2^n addressing. Plus the memory hierarchy and I/O tables RGPV asks as 7-markers.

Memory hierarchy and storage paths (draw this)

CPU-side automatic path:  Registers -> Cache -> Main RAM/ROM
OS-mediated storage:      Main RAM <-> page cache/buffers <-> disk
Archival path:            OS/operator backup or restore <-> tape

Rule: within the fast CPU-side path, speed and cost/bit fall while capacity rises. Hardware automatically checks registers, cache, then RAM. Disk access is a separate OS-mediated I/O path; tape is archival and normally operator- or schedule-mediated.

Diagram — CPU access and storage paths (draw this) 
AUTOMATIC CPU-SIDE ADDRESS PATH
  CPU core + registers <--> Cache L1/L2/L3 -- cache miss --> Main RAM (DRAM)
  The CPU does not automatically search disk or tape.

MISSING PAGE: OS-MEDIATED SECONDARY STORAGE
  Main RAM -- page fault if absent --> OS handler + filesystem + I/O driver
    --> page cache / I/O buffers <--> disk controller <--> HDD / SSD / optical
  I/O completion --> page table update --> CPU resumes from Main RAM

DIRECT FILE REQUEST: ALSO OS-MEDIATED
  Application --> OS filesystem + I/O driver <--> buffers <--> controller <--> disk

ARCHIVAL STORAGE
  OS/operator backup or restore <------ sequential I/O -------> tape

The 1024 ladder — memorize (numeral machine)

8 bits = 1 byte (B)
1024 B = 1 KB | 1024 KB = 1 MB | 1024 MB = 1 GB | 1024 GB = 1 TB
2^10 = 1024 (about 1K);  2^20 (about 1M);  2^30 (about 1G)
Worked memory ladder: 5 GB → 5,120 MB → 5,242,880 KB → 5,368,709,120 bytes. Moving downward multiplies by 1024; moving upward divides. A 32-bit address bus in a byte-addressable system reaches 232 bytes = 4 GB.

I/O devices — two tables

Input (into computer)Output (out of computer)
Keyboard, mouse, scanner, mic, webcam, joystick, OMR/OCR/MICR, touch screen, light penMonitor (soft copy), printer/plotter (hard copy), speaker, projector

Volatile defined (exam line): memory that loses everything when power goes off. Example: half-typed Word assignment vanishes in a power cut unless saved — RAM held it, disk never got it. Non-volatile (ROM, HDD, SSD, pen-drive) survives.

Why SRAM is fast and DRAM is dense: SRAM stores each bit in a flip-flop (6 transistors, no refresh → fast, costly → cache). DRAM stores each bit as charge in a tiny capacitor (1 transistor → dense, cheap) that leaks, so it must be refreshed thousands of times a second (→ slower → main RAM). One sentence — "capacitor leaks, flip-flop holds" — answers every SRAM-vs-DRAM viva.

Impact printers strike paper through ribbon (dot-matrix: noisy, prints carbon-copy railway tickets and bank forms). Non-impact printers never touch paper (inkjet sprays ink — home colour prints; laser fuses toner — fast office printing). One line each suffices — with these examples attached.

Formula: x1024 going down (MB->KB->B), /1024 going up

Numeral traps
  • 1000 vs 1024: memory uses 1024. Writing 1 KB = 1000 B loses the mark.
  • Bits vs bytes: 8× slip. Convert to bytes FIRST, bits only at the end (×8).
  • Direction: up (B→KB) divides; down (GB→MB) multiplies. Wrong direction = absurd answer.
  • Cache vs RAM: cache is SRAM (fast, small); main RAM is DRAM. Swapping them is a classic viva trap.
Special lines for extra marks
  • "Cache exploits locality of reference: recently used data is likely to be reused, so SRAM cache hides DRAM latency."
  • "A 32-bit address bus addresses 2^32 bytes = 4 GB, the classic RAM ceiling of 32-bit systems."
  • "SSDs store in flash with no moving parts, hence faster seek and shock resistance than HDDs."
  • End numerals with boxed answer + unit (KB/MB/GB).
Exam tips
  • Draw the CPU-side hierarchy and separate OS-mediated storage path for any "memory hierarchy" 7-marker.
  • RAM/ROM/cache/HDD/SSD table = 5 rows minimum; add volatile + example columns.
  • I/O question: give 4 inputs + 4 outputs + 1 line on printer types.

Model answer · 7 marks

Memory hierarchy + primary vs secondary

Memory is arranged so the CPU gets the fastest possible access without paying for the largest capacity at every level.

CPU-SIDE AUTOMATIC PATH
  CPU core + registers <--> Cache L1/L2/L3 -- cache miss --> Main RAM (DRAM)
  Within this path, nearer CPU means faster, smaller, and higher cost/bit.

MISSING PAGE: OS-MEDIATED SECONDARY STORAGE
  Main RAM -- page fault if absent --> OS handler + filesystem + I/O driver
    <--> page cache / I/O buffers <--> disk controller <--> HDD / SSD / optical

DIRECT FILE REQUEST: ALSO OS-MEDIATED
  Application --> OS filesystem + I/O driver <--> buffers <--> controller <--> disk

ARCHIVAL STORAGE
  OS/operator backup or restore <------ sequential I/O -------> tape

DISK AND TAPE ARE NOT AUTOMATIC CPU CACHE LEVELS
  1. Primary: RAM is volatile working memory and ROM is non-volatile firmware; cache is CPU-side SRAM that exploits locality.
  2. Secondary storage: the OS and I/O drivers move blocks between buffers/controllers and HDD, SSD, or optical media.
  3. Path rule: hardware automatically uses registers, cache, and RAM. Missing pages and file requests invoke OS-mediated disk I/O; tape is a separate archival path.

Exam close: “Within the CPU-side path, memory nearer the CPU is faster and smaller; OS-mediated storage and archival tape are separate paths.”

Model answer · 5 marks

RAM vs ROM vs cache; HDD vs SSD

Compare devices using the same columns so the examiner can tick each distinction quickly.

+---------+------------+---------------------+-------------+------------------+
| DEVICE  | VOLATILE   | TECH / ACCESS       | SPEED       | REL COST/CAP/USE |
+---------+------------+---------------------+-------------+------------------+
| RAM     | yes        | DRAM/SRAM           | varies      | work data        |
| ROM     | no         | firmware            | varies      | boot             |
| CACHE   | yes        | SRAM; reuse         | very fast   | locality         |
| HDD     | no         | magnetic            | slow random | cheap; TB bulk   |
| SSD     | no         | flash; no parts     | fast random | higher; OS/apps  |
| OPTICAL | no         | laser disc          | slow        | media/archive    |
| TAPE    | no         | magnetic; seq       | sequential  | low-cost backup  |
+---------+------------+---------------------+-------------+------------------+
  1. RAM loses contents at power-off; ROM retains firmware; cache is fast SRAM and is usually volatile.
  2. SRAM is fast and costly; DRAM is dense, cheaper, and needs refresh.
  3. HDD is slower and shock-sensitive because it has moving parts; SSD is faster and shock-resistant because it uses flash.

Exam close: state one correct use for every device and never call cache “permanent.”
