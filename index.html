02 how to use it

step 1

Learn one page

Open a topic. Read the Lesson tab, then flip to Cheat-Sheet — that tab is built to be the only thing you read the morning of an exam.

Diagrams are plain ASCII on purpose, so you can redraw them on paper.

step 2

Test yourself

Five MCQs per topic mark themselves and explain the answer. Then run the PYQ drill sets under a timer.

Tick topics off on a unit hub; your progress is saved in this browser.

step 3

Fix what's wrong

Spot a mistake or a better explanation? Add a comment on the page and it lands in the repo's Discussions.

04 how it behaves

▣

Hover anything

Hover a link and the target page peeks open before you leave. Hover a figure and a copy button appears. Hover a block and you can copy a link straight to that section.

Borrowed from Obsidian and Notion, respectively.

〈

Keyboard does the work

Ctrl K search, [ index, o sections, f focus mode, ] next topic.

Press ? anywhere for the full sheet.

◆

Every page knows its place

Under each title sits a properties row — subject, unit, how many MCQs, how long it takes to read — pulled from the same data as the sidebar so the two cannot disagree.

Notion's database row, in a static page.

◉

Graphs are generated, not drawn

Function graphs are plotted from the formula and then checked: the curve has to bend, pass its labelled points, and put the secant parallel to the tangent.

A hand-drawn curve is exactly what goes quietly wrong.

05 contribute

◆

Leave a comment on any page

Every topic page has a Comments & corrections box at the bottom. No account here — sign in with GitHub and your note goes straight into the repo's Discussions, where everyone can see it.

Good comments get folded into the page and credited. That is the fastest path to a change; no git required.

▲

Or open a pull request

The pages are plain HTML with no framework. Edit a file in the GitHub web editor, or clone and run python3 tools/sync-web.py to rebuild the site.

The house style is written down in notes/note.md — read it before you restructure anything.

▣

Keep the pages portable

Every page must keep working when opened straight off a hard drive or sent over WhatsApp. That means: relative links only, no build step, no external CSS or JS beyond this site layer.

Do not add inline SVG, Mermaid, or web fonts to a topic page. Diagrams stay portable ASCII.

●

Colour tokens are a contract

--ink #e6e3dc, --paper #14161b, --accent #e0a370. Restyle once in assets/site.css, not per file.

Hover states change a border or a text colour — never a whole filled block.
